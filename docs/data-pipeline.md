# 单机预训练语料流水线

流水线只读取用户提供的本地 JSONL/TXT，不下载语料，不运行 GPU 或正式预训练。
规范化文本、全文去重索引、原文分组、采样和排序均存储在 SQLite。
每条记录及 Token 缓冲都有上限；空间随总量增长的是磁盘文件，不是 Python 文档/Token 列表。

## 阶段与发布

```
原始快照 → Normalize/Quality → 全文去重/分组 → 稳定采样/分片/混合/划分
         → Train-only Tokenizer 训练或加载 → 各 Split 流式 Tokenize
         → 完整文件/Token/隔离审计 → dataset-manifest.json 原子发布
```

`.pipeline/plan.json` 记录输入内容与处理参数身份，各 `*.stage.json` 是阶段完成标记。
只有对应内容 Key、文件大小和 SHA256 都匹配才会复用阶段；SQLite 产物还在发布前执行完整性检查。
输入变动、清洗/去重/Seed/配比参数或实现版本不同，都会拒绝复用，要求新的输出版本目录。
`--tokenize-only` 默认继承已保存的准备计划；显式传入冲突参数会报错。

文件在目标目录内先写临时文件、flush/fsync，关闭后原子替换；POSIX 同步目录。
最终 Manifest 是数据集完整发布的提交标记，未出现该文件时不能将目录当作完整数据集使用。
例如 `val.bin` 生成失败后，已校验的清洗、去重、划分和 `train.bin` 可直接复用。
不会从残留 `.tmp` 加载数据。已发布版本只能验证或只读复用，不能换 Tokenizer、重新混合或覆盖。
运行中不可同时修改原始数据；每次准备启动重新计算输入哈希，首次清洗读完后再次核验原始快照。

原始文件哈希计算仍需顺序读取字节，复用省去的是 JSON 解码、清洗、去重、排序与已完成的编码。
SQLite 工作目录可用 `--temp-dir` 放到容量足够的本地磁盘；外置临时目录按输出路径隔离。
发布后审计只需最终产物；清理工作 DB 后仍可审计，但不能再复用相应未发布阶段。

## 规范化与质量

- NFC、换行及文本空白规范化；代码保留缩进和网页标记，不使用中文字符白名单。
- `zh/en/code/mixed/unknown` 为字符比例和代码标志的启发式分类，可用来源/记录 Category 显式提示。
  分类不是专业语言识别模型，混合语言和代码片段可能误分类，审计需结合来源检查。
- 异常 UTF-8/Unicode、空白、短文本、低信息密度、重复句/段、大量广告/联系方式分别计数。
  数字和数学公式算信息字符；英文和代码使用各自阈值；代码默认不做重复句和近重复删除。
- 默认每条原始记录最多 1 MiB、规范化父文档最多 200,000 字符。
  超过记录/父文档上限会排空并拒绝整条，绝不把残余尾部重新解释成新文档。
- 超过 `max_chars` 的文档按段落切分，极长单段按字符上限硬切。片段保留共同 `parent_id`。
  JSONL 的外部 `parent_id` 会在来源命名空间内分组。TXT 的空行分隔段落共享文件父组，
  因此同一本 TXT 的段落不会分散到不同 Split。
- 输入元数据缺失时 `source/license/declared_category` 为 `unknown`；`category/language` 是明示来源提示或启发式分类结果。
  License 是来源声明，不是自动验证的授权。
  使用者应确认来源与用途，并通过 `license_policy.allow/exclude_unknown` 排除不适用来源。

示例配置默认排除 Unknown License；修改路径并填写已确认的来源许可之后再运行。
允许的开关与阈值见 `configs/pretrain-corpus.example.json`，可关闭过滤器进行对照审计。

## 全文去重与隔离

精确去重以规范化全文 SHA256 建立磁盘主键，跨文件、跨来源共用索引。
文本精确键折叠空白；代码保留有意义的缩进。重复来源的代表按优先级降序、内容与元数据稳定键选择。

近重复使用全文字符 4-gram 集合生成 64-bit SimHash，默认 Hamming 半径 4；
用 5 个不相交位段建立 SQLite 桶索引。候选再做完整 4-gram 集合 Jaccard ≥ 0.85 的确认。
算法依据：[Manku 等，Detecting near-duplicates for web crawling (WWW 2007)](https://research.google/pubs/detecting-near-duplicates-for-web-crawling/)。

Hamming 半径内指纹至少有一段完全相同，但这不保证所有高 Jaccard 文本都落在该半径内。
共同开头不足以删除文章，必须经过全文相似度确认。标题更换和少量修改通常可检出，
大量改写、很短文本、相似语义但不同字面内容可能漏检；字符集合也可能把词序不同的文本误判相似。
这不是语义去重或数学意义的零近重复保证。

所有被检出的边在磁盘上合并为传递组；父文档和切分后片段均执行检测。
分片后再次去除完全/近似重复片段，并把其原文划分组联结，避免共同片段泄漏。
同一近重复组只保留一个稳定代表，原文分组不意味着删除原文中的其他不同片段。
默认候选上限为每文档 2,000；桶过密会明确报错停止，不截断候选后声称已完成去重。
可以收紧半径、调整有审计依据的候选预算，或显式选择 `--dedup-method exact`。

分组完成后用 `SHA256(seed, group_id)` 分桶，默认 96/2/2；输入路径遍历顺序不参与随机决策。
小数据的真实比例可能偏离目标，甚至没有 Val/Test，不会拆散原文凑数；应增加独立文档组。
所有精确文本、原文及已识别近重复组都检查跨 Split 隔离。未检出的近重复不宣称不存在。

## Token 配比

配置支持按 `source` 或 `category` 设置权重和**估算 Token 预算**。
通过按类别配置 `chars_per_token` 估算文档 Token 数，用稳定的磁盘顺序选择整片段，
不按文档条数等比例抽样，不重复抽取耗尽来源，不跨集合重新采样。
目标是近似 Token 份额，真实编码后的 Token 数/比例也会记录，二者不保证完全相等。

`token_budget=0` 表示保留全部去重数据，目标权重仅供审计参考，不承诺把现有数据强制变成目标比例。
有预算时，每个实际存在的桶都需显式权重；零权重表示有意不选取该桶。
来源耗尽、短缺、文档长度造成的预算余量均报告，未静默重分配或过采样。
80/15/5 只是三来源示例，可调整为包括混合文本/基础推理/Unknown 的实验方案。

## Tokenizer 与 BIN

已有模型必须加载原来的 Tokenizer：`--tokenizer .../tokenizer.json`。
只有新模型实验才使用 `--train-tokenizer --vocab-size ...`；该模式只迭代 Train，
默认最多 8,000,000 字符，BPE 训练器的内部词频内存受此明确预算约束。
Val/Test 从不进入词表拟合。独立 `train_tokenizer.py` 识别流水线的 held-out 文件，
核验 Split 哈希，并拒绝覆盖现有 Tokenizer；原有 `--forbid` 也检查被复制改名的完整文件。
无法识别任意外部文本文件是否曾属于其他任务的验证集，需维护原始来源记录。

BIN 按选定文档顺序编码，每篇追加 EOS，逐条验证 Token 在词表和 uint16 范围内。
默认 1 MiB 写缓冲，单文件格式固定为 little-endian uint16，不聚合完整 Token 数组。
仍输出 `train.bin/val.bin/test.bin`；`PackedPretrainDataset` 和训练游标语义不变。

## 审计与身份

`dataset-manifest.json` 包含输入大小/SHA、清洗版本/参数、过滤与去重统计、来源、划分、
Tokenizer 指纹、各 Split 文档/字符/Token 直方图、来源与类别 Token 分布、所有文件 SHA256。
内容身份绑定输入内容、影响内容的参数、实现/依赖版本、Tokenizer 与最终文件内容；
生成时间、Git 提交注释和执行耗时不参与身份。SQLite 缓存大小、提交批次、写缓冲属于运行参数。

审计逐字节核验最终文件哈希、词表指纹和全部 BIN Token 范围；用临时 SQLite 重算全部
精确文本重叠、父组和已知组隔离。`--retokenize` 额外将全部文本重新编码并与 BIN 比较；
默认 Token 长度/来源 Token 统计注明为生成记录，不伪装成独立重新编码。
`--verify-inputs` 可重新核验原始快照，默认不要求发布后继续保留原始路径。

所有报告明确列出已执行、未执行和近似检查；文件损坏、词表不匹配或确定性泄漏退出非零。
训练入口在 `.bin` 旁发现数据 Manifest 时会核验相应 BIN 和 Tokenizer，并记录 `dataset_content_id`，
与 PR #2 的文件 SHA256 和严格 Resume 校验共同工作。新数据版本应启动新训练计划，不能当作旧任务 Resume。

## 测量与限制

运行 `python scripts/benchmark_data_pipeline.py --documents 10000 100000 --out /tmp/data-benchmark`。
脚本不下载数据，在新子进程测量 CPU 全流水线与完整审计后的峰值 RSS，报告导入后的基线、
增量峰值、每阶段耗时、文档/Token 吞吐和隔离统计；不在普通 CI 中断言易波动的绝对 RSS。
默认记录和缓存上限面向处理器增量内存 512 MiB 以内，具体平台和 BPE 字符预算会影响实际值。

仍需足够临时磁盘空间存放 SQLite 副本/索引和中间文本，通常数倍于规范化文本；
大原文、热桶和来源数量会影响吞吐。默认最多 128 来源、10,000 输入文件，控制面元数据也有界。
未实现分布式处理、动态课程、并发写同一输出目录或物理断电测试；单输出目录只允许一个写入任务。

### 本次实测（合成语料）

Linux、Intel i7-11850H、Python 3.11.17、CPU 单线程、SQLite 缓存 16 MiB、加载 264 词表的合成 ByteLevel Tokenizer。
生成耗时包含发布前审计；峰值 RSS 还包含独立的完整重新编码审计。每个规模使用新子进程。

| 文档数 | 实际 Token 数 | 生成秒数 | 文档/s | Token/s | 总峰值 RSS MiB | 相对导入后峰值的增量 MiB |
|---:|---:|---:|---:|---:|---:|---:|
| 10,000 | 4,370,793 | 13.544 | 738.34 | 322714.45 | 540.46 | 43.37 |
| 100,000 | 43,797,053 | 166.730 | 599.77 | 262682.60 | 545.33 | 48.24 |

PyTorch 导入后的基线峰值约 497 MiB，不能把增量误称为整个进程内存。
两个规模的三组跨 Split 精确重叠均为 0，已知近重复组跨 Split 为 0。
7 组人工构造正负对照中，5 组重复全部识别、2 组不同内容全部保留；仅表示这些样例，
不是现实语料上的 100% Precision/Recall 保证。100,000 篇随机内容数据本身无预设重复。
