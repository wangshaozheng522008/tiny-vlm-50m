# MiniLLM 中文生成退化诊断

## 复现

基于 PR #16 合并提交 `7c9c6b0e467cb692340e3da8534822019cfe3f95`。使用原工作区的冻结语料、Step 0、Step 123、恢复状态和 INT4。入口逐项核对 artifact SHA256、初始权重谱系、冻结内容 ID、Tokenizer 指纹和实际窗口消费，随后从 FP32 重新导出并逐张量比对 INT4 内容。默认输出到 `reports/v4-language-degeneration-diagnostics/`，每组实验独立发布带 SHA256 的清单。输出目录已有证据时选用新路径。

```bash
.venv/bin/python scripts/diagnose_language_generation.py pilot --device cuda
.venv/bin/python scripts/diagnose_language_generation.py memorize --device cuda
```

`pilot/` 包含 `models.json`、四种口径的 `token-distributions.json`、三份 Top-20 概率轨迹及对应的全词表 NPZ、固定前缀逐条解码、300 条评测的逐条解码、量化配对、Train 抽样窗口和污染观测。NPZ 键是前缀 ID，数组行从第一个预测位置起顺序排列，列按 Token ID 排列。每种采样设置使用 Seed 42、43、44，按输出预算分组后以固定顺序左填充批次。Greedy 每个惩罚档执行一次。历史单条正式 Greedy 结果保留在 PR #16。带重复惩罚的实验只用于诊断。

`memorization/` 包含 120 条原创样本、固定配置、每 25 Step 的 Loss、teacher-forced 准确率、10 条训练前缀的实际续写和 Token ID。已运行的 Loss 曲线在报告根目录的 `memorization-loss-curve.svg` 和 `memorization-loss-curve.csv`。本次整步扩展容量复核在 `expansion/expansion-budget.json`，真实 EOS 停止复核在 `real-sampled-eos.json`。

同一 T1200 和软件环境下复跑 `pilot`，三种权重的 2,253 条生成文本与 Token ID 全部一致，三份全词表概率数组逐字节一致。`pilot-reproduction/` 保留复跑结果，配对校验写入 `reproduction-summary.json`。

## 正确性与污染审计

确认了两个 Attention Mask 边界错误。直接向模型传入含有效标签的掩码时，原 Loss 不排除被遮蔽的因果转移。原生成路径也只在 prefill 传入掩码，后续重算与 KV Cache 解码重新看到了遮蔽位置。现在 Loss 和梯度累积共用有效标签定义，生成全程保留键掩码。历史正式训练是无填充的完整窗口，历史正式生成无掩码。另修正提示恰好占满上下文时的生成预算。

CPU 小模型用人工标签验证单次因果位移、Ignore Index、填充、求和交叉熵和不等微批的梯度累积。真实 Step 123 完整窗口贡献 1,023 个目标，前缀未来 Token 扰动对先前 logits 的最大影响为 0。12 步 KV Cache 对照的最大 logit 差为 `6.68e-6`，分块 RoPE 对照为 `4.29e-6`，两条 Greedy 序列一致且没有近并列分歧。真实权重通过 2,048 上下文边界验证，另外以真实 logits 的专用 Seed 300 抽到 EOS（ID 2，首步概率 0.201%），生成恰好在 EOS 停止。Step 0 到 Step 123 的 147 个状态字典张量条目均发生变化，最终模型与已提交恢复状态逐张量相同。

代表性 Train 测量以 Seed 42 固定抽取 64 个完整窗口，共 65,472 个目标位置。中文通用／中文百科／中文教育／英文通用位置数为 29,344／19,124／9,665／7,339。跨类别窗口逐标签定位归属。窗口索引的 SHA256 为 `7004c202d0a058f9c905194155bdf563e379a09c04f3eb58b66b36b5b3c44e2c`。

## 根因判断

| 等级 | 证据与边界 |
|---|---|
| `DECODING_AMPLIFIED_DEGENERATION` | 确认。逗号和换行的 Top-1 选择会反馈到下一步，维持循环。采样打破循环，自动评分仍为 0/197，人工查看也未显示稳定的连贯续写。 |
| `LIKELY_UNDERTRAINING` | 同一架构在原创小样本达到记忆上限，真实 Pilot 的代表性 Train 和固定后缀 Loss 下降，但参考下一 Token 排名为 1,112–8,183。1M 的 123 次更新建立了频率偏好，中文生成质量仍有限。随训练量增长的效果待独立 2M 实验验证。 |
| `CONFIRMED_IMPLEMENTATION_BUG` | 确认带掩码的 Loss 和生成传播错误，以及满上下文预算边界。对照显示它们未解释本次无填充、无掩码的正式 Greedy 退化。 |
| `INCONCLUSIVE` | 语料中少数标点确实高频，但相对于冻结编码，训练监督没有额外富集标点。尚无保持训练量固定、只改变语料分布的因果对照。现有证据不足以把退化归为语料分布或 Tokenizer 故障。 |

工程证据支持在新来源范围批准后开展 2M。当前库存无法按配比构建 4M，100M 仍需独立供给与准入验证。

## 复审修复

- **RoPE 与填充**。有掩码时，每行按可见 Token 的累计位置计算 RoPE。KV Cache 仍使用物理槽位，传入的掩码覆盖已缓存和新输入的位置，上下文上限也按物理槽位检查。旧实现在 Nano 夹具中追加首个后续 Token 时，右填充与无填充的最大 logit 差约为 0.0142。真实 Step 123 的五条前缀各比较 12 个生成步骤，无填充、左填充及右填充的 Token 序列相同，含 KV Cache 和全前缀重算的四组最大 logit 偏差均低于 `8.6e-6`。
- **历史 Greedy 门禁**。诊断入口要求历史配置及任务覆盖一致，逐题对照提示 Token、输出预算、生成 Token 序列、停止 ID 和停止原因。任一差异使诊断失败，并在错误中标明首个差异及字段。成功证据写入 `historical-greedy-check.json`，含历史预测文件的 SHA256。
- **扩展容量**。按配置的十进制比例进行有理数运算。`strict_exact_ratio_bounds` 报告精确整数配比的算术上界，`max_feasible_seeded_full_update_preview` 记录配置容差下实际通过整文档打包和 sampler 重放的容量。预览仍要求冻结语料满足每类名义配额，且冻结与消费的实际比例都通过容差。来源审批和禁止重复采样的正式门禁照常适用。
